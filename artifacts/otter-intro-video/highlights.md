# otter 소개 모션 영상: 강조점 정리

영상 제작 전에 "무엇을 보여 줄지"를 고정하는 문서다. 모든 주장은 저장소 기준(2026-10-20, master `132e122`)으로 확인한 사실만 쓴다. 근거는 각 항목 끝 `근거:`에 적었다.

## 1. 한 줄 메시지

> **실행할수록 쌓이는 코딩 에이전트.**
> 대화는 사라져도 계획·승인·실행 이력은 남아 다음 작업의 지식이 된다.

- 영상 전체가 이 한 문장을 증명하는 구조여야 한다.
- 대비 구도: 일반 에이전트 = 대화 끝 → 증발 / otter = 대화 끝 → 축적.

## 2. 타깃과 톤

- 타깃: Codex·Claude Code·Ollama를 이미 쓰는 개발자. "에이전트가 뭔지"는 설명하지 않는다.
- 톤: 차분하고 단단함. 과장 형용사 대신 화면 속 실제 명령과 결과로 말한다.
- 길이: 60~75초 본편 + 15초 숏폼 컷.

## 3. 강조 우선순위

| 순위 | 강조점 | 본편 비중 | 역할 |
|---|---|---|---|
| 1 | 실행 이력이 자산이 된다 | 약 40% (오프닝 + 본론 + 엔딩 회수) | 영상의 주제. 처음과 끝을 모두 잡는다 |
| 2 | 엔진을 가리지 않는다 + 멀티 모델 콤보 | 약 25% | 두 번째로 큰 장면. "어떤 모델이든 같은 자산으로" |
| 3 | 자동 스킬 + 의도 라우팅 | 약 15~20% | 세 번째 장면. "알아서 돕되 멋대로 하지 않는다" |
| 보조 | 통제된 실행, 워크트리 격리, 한 줄 설치 | 합쳐서 약 15% | 신뢰와 진입 장벽 해소용 짧은 컷 |

원칙: 2·3순위 장면도 끝은 항상 1순위(이력이 쌓이는 블록)로 돌아온다. 어떤 엔진을 쓰든, 어떤 스킬을 쓰든 결과가 같은 자산으로 쌓인다는 점을 반복해서 보여 준다.

## 4. 핵심 강조점

### ① [1순위] 실행 이력이 자산이 된다
- 말할 것: 도구 실행 결과는 append-only SQLite 로그로 남고, `otter-wiki capture`가 이를 출처가 연결된 위키(개념·엔티티 페이지)로 쌓는다. 위키는 다음 작업의 컨텍스트로 다시 쓰인다(`/memory`). 지난 작업은 `/sessions`, `otter --resume`으로 다시 이어간다.
- 보여 줄 것: 대화 말풍선이 흩어지는 대신 작은 블록(로그 행)으로 떨어져 쌓임 → 블록이 위키 페이지 카드로 조립 → 카드에서 선이 뻗어 다음 대화로 연결되는 루프. 루프를 한 번 더 돌릴 때 카드가 늘어나 "쓸수록 쌓인다"를 시각화.
- 화면 카피: `대화는 사라진다. 이력은 남는다.` / `쓸수록, 다음 작업의 근거가 쌓인다.`
- 신뢰 포인트: 인자·출력 본문은 저장하지 않음(메타데이터만). 원본 스냅샷은 불변, 해시로 무결성 검사.
- 근거: `README.md` 기능 1·2·3, `knowledge/AGENTS.md`, `bun scripts/otter-wiki.ts status` → sources 5 / compiled 5 / problems 0.

### ② [2순위] 엔진을 가리지 않는다 + 멀티 모델 콤보
- 말할 것: Ollama(로컬)·Codex·Claude CLI 중 무엇을 써도 이력은 같은 형식으로 쌓인다. 콤보로 planner/worker/reviewer 역할마다 다른 모델을 쓴다. 추천 프리셋을 제공한다(예: "Astra plans, Luna executes, Fable reviews"). 대화 중에도 `/model`로 모델을 바꿀 수 있다.
- 보여 줄 것: local / codex / claude 세 칩이 각자 다른 경로로 들어와 **하나의 이력 레인**으로 합류 → 그 레인 끝에서 ①의 블록이 똑같이 쌓임. 이어서 역할 슬롯(Planner / Worker / Reviewer)에 서로 다른 모델 칩이 하나씩 스냅 인.
- 화면 카피: `엔진은 달라도 기록은 하나.` / `역할마다 가장 잘하는 모델로.`
- 인증 포인트: otter는 자격 증명을 읽거나 저장하지 않는다. 각 CLI의 공식 로그인(`otter login codex|claude`)을 그대로 쓴다.
- 근거: `README.md` 엔진 무관·멀티 모델 콤보, `framework/src/hosts/combo-presets.ts`, 커밋 `859d42f`(세션 중 모델 변경).

### ③ [3순위] 자동 스킬 + 의도 라우팅
- 말할 것: 모델이 대화 맥락을 보고 필요한 스킬을 스스로 불러 쓰고 답변 앞에 `Skills used:`로 표시한다. 모호하거나 설계 수준의 요청은 보내기 전에 [채팅 계속 | deep-interview | ralplan | 취소]를 제안한다. 워크플로는 절대 자동으로 시작하지 않는다.
- 보여 줄 것: 입력창에 모호한 요청 입력 → 전송 직전 라우팅 칩 4개가 떠오르고 사용자가 하나를 고름. 다른 컷에서 답변 머리에 `Skills used: llm-wiki` 태그가 슬라이드 인. 마지막에 사용된 스킬도 이력 블록으로 떨어져 쌓임(①로 회수).
- 화면 카피: `알아서 돕되, 멋대로 하지 않는다.`
- 근거: `README.md` 워크플로·스킬, 의도 라우팅, 자동 스킬 문단.

### 보조 컷 (짧게, 신뢰와 진입 장벽 해소용)
- **통제된 실행**: `/plan` → 사람이 `/approve` → 실행, 원장에 기록. 계획은 절대 자동 승인되지 않는다. 카피 `승인 없이는 실행하지 않는다.` 근거: `README.md`, `cli.ts` 사용법 "Plans are never auto-approved."
- **워크트리 격리**: 승인된 계획은 별도 작업 트리(`wf-<id>`)에서 실행, 끝나면 [적용 | 유지 | 버리기]. 적용 전에는 내 체크아웃 그대로. 카피 `반영은 내가 고른다.` 근거: `README.md`.
- **한 줄 설치**: `curl … | bash`, 이후 `otter` 입력하면 바로 새 대화. 카피 `한 줄이면 된다.` 근거: `README.md`, PR #57.

## 6. 숏폼(15초) 컷

1. 0–5s: [①] 말풍선 증발 vs 블록 축적, 좌우 대비 화면 → 위키 카드로 조립
2. 5–10s: [②] 세 엔진 칩이 한 레인으로 합류해 같은 블록이 쌓임
3. 10–13s: [③] `Skills used:` 태그 + 라우팅 칩
4. 13–15s: "실행할수록 쌓이는 에이전트. otter"

## 7. 비주얼 가이드

- 핵심 메타포: **흩어지는 말풍선 → 쌓이는 블록**. 모든 장면이 이 재질 대비를 반복하고, 2·3순위 장면도 블록으로 끝난다.
- 색: 다크 배경 + 한 가지 포인트 색(축적 순간에만 사용). 엔진 칩 3개는 채도 낮은 서로 다른 색, 합류 후에는 포인트 색 하나로 통일(= 기록은 하나).
- 타이포: 카피는 짧게(12자 내외), 명령어는 모노스페이스로 실제 문자열 그대로.
- 실제 화면 인서트: TUI 스크린 녹화는 ③과 보조 몽타주에만 짧게. 나머지는 추상 모션.

## 8. 말하지 말 것 (사실과 다르거나 확인되지 않은 것)

- "완전 자동", "알아서 다 해 준다": 실행은 항상 사람 승인 뒤다. 자동 스킬도 동의가 필요 없는 스킬만 대상이고, 워크플로는 자동 시작하지 않는다.
- "샌드박스/격리 보장": 사용법에 "no process or filesystem containment is claimed"라고 명시되어 있다. 워크트리는 **체크아웃 보호**이지 보안 격리가 아니다.
- "출력 전체를 기록": 인자·출력 본문은 저장하지 않는다.
- "쓸수록 빨라진다/똑똑해진다" 같은 정량적 개선 주장: 측정 근거가 없다. "근거가 쌓인다", "다시 쓸 수 있다"까지만 말한다.
- 성능 수치, 사용자 수, 벤치마크: 근거 자료가 없다.
- 특정 모델 이름을 기본값처럼 표현하기: 프리셋 예시일 뿐이다.

## 9. 기존 영상과의 차이

- `make.py`/`otter-intro.mp4`는 슬라이드 + 내레이션 구성(10장면)이었다.
- 이번 영상은 **메타포 중심 모션**으로 바꾸고, 1순위(이력 → 자산)에 시간을 몰아준다. 기존 영상에 없던 ② 콤보, ③ 자동 스킬·의도 라우팅을 주요 장면으로 추가한다.
