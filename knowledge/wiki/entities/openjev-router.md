# OpenJev 스킬 라우터

> 위키 운영·근거 규칙은 [`knowledge/AGENTS.md`](../../AGENTS.md), 도구 실행 결과의 증거 한계는 [도구 결과 근거](../concepts/tool-outcome-evidence.md)를 따른다.

## 현재 프로젝트 상태

저장소의 프로젝트 설정 `.otter/otter.jsonc`는 `skill_router.mode`를 `suggest`로 설정한다. 이는 이 프로젝트가 턴별 스킬 **추천**을 선택적으로 요청한다는 뜻이다. 공유 라이브러리 기본값은 `framework/src/config.ts`의 `DEFAULT_CONFIG.skill_router.mode: "off"`다. 프로젝트 설정이 라이브러리 기본값보다 우선한다.

`framework/README.md`의 기존 `shadow` 설명도 현재 프로젝트 설정과 일치하는 `suggest`로 갱신했다. `shadow`는 관찰 전용 대안으로 남아 있다. 실행 설정과 설명이 다시 달라지면 출처를 대조하고 모순을 표시한다.

`suggest`의 효과는 현재 턴에 선택적 조언을 덧붙이는 것뿐이다. 추천 결과가 스킬을 자동 로드하거나, 모드를 활성화하거나, 도구를 실행하거나, 권한을 바꾸지 않는다. 명시적 권한 검사와 모드 규칙을 대체하지 않는다. 스킬 후보는 프로젝트 로컬 `.opencode/skills/<name>/SKILL.md`의 메타데이터이며, 허용 목록 및 현재 권한 조건을 적용한다. 스킬 본문을 라우터에 보내지 않는다.

## 연결과 개인정보 경계

프로젝트 설정은 엔드포인트를 직접 지정하지 않는다. 저장소의 기본 엔드포인트는 `http://127.0.0.1:8080`이고, 라우터는 리터럴 HTTP loopback 주소(`127.0.0.1` 또는 `::1`)만 허용하며 리디렉션을 거부한다. `scripts/openjev-local.sh`도 환경 변수로 별도 재정의하지 않는 한 서버를 `127.0.0.1`에 바인딩한다. 이 위키는 호스팅 API, API 키, LAN 바인딩 또는 서비스 설정 변경을 전제로 하지 않는다. 클라이언트의 loopback URL만으로 별도로 all-interface에 바인딩된 서버가 보호된다고 간주하지 않는다.

라우팅에는 현재 사용자 텍스트와 후보 이름·설명이 쓰인다. 사용자 텍스트가 2,000자를 넘으면 잘라 보내지 않고 추천을 생략한다. 구현 문서는 일반적인 자격 증명 패턴을 발견하면 추론을 중단한다고 설명하지만 탐지는 완전하지 않다. 기밀 내용을 라우터 입력에 넣지 말고, 라우터 추천을 실행 권한으로 취급하지 않는다. 취소는 이미 시작된 로컬 추론 작업이 중단됐음을 보장하지 않는다.

## 근거와 한계

구현·설정 근거는 `.otter/otter.jsonc`, `framework/src/config.ts`, `framework/src/routing/router.ts`, `framework/README.md`의 “Optional OpenJev skill recommendations” 절, `scripts/openjev-local.sh`다. 프로젝트 README는 평가와 부하 시험 전 프로덕션에서 추천을 켜지 말라고 경고하며, 확률·마진 기준도 보정된 정확도나 권한 보장이 아니라고 설명한다.

이 자료는 설정과 설계 경계를 설명할 뿐 추천 품질이나 업무 결과를 측정하지 않는다. 검토된 자료에 측정된 업무 영향이 없으므로 **측정된 비즈니스 임팩트는 알 수 없다**. 정확도·시간 절약·생산성·성공률을 추정하거나 생성하지 않는다. 프로젝트 모드가 `suggest`라는 사실만으로 실제 추천이 성공했거나 스킬이 적용됐다고 결론내리지 않는다.
