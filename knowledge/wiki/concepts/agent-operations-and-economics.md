## 과업 완료 비용을 본다

A04는 매 요청에 누적 문맥이 다시 입력되고 출력·thinking·재시도·자식 실행이 모두 비용을 만든다고 설명한다. 낮은 토큰 단가가 싼 완료를 보장하지 않는다. 검증 수단이 없어 같은 실수를 반복하는 세션은 더 비싼 모델이나 더 높은 effort보다도 비쌀 수 있다.

다음은 위키가 정리한 회계 틀이다. 공급자의 실제 usage 정의에 맞춰 **서로 겹치지 않는 항목**으로 계산해야 한다.

```text
API 비용 = 신규 입력 × 입력 단가
         + 캐시 쓰기 × 해당 TTL의 쓰기 단가
         + 캐시 읽기 × 읽기 단가
         + 출력(과금 대상 thinking 포함) × 출력 단가
         + 별도 도구·서비스 요금

관측한 완료 과업당 비용 = 범위 내 모든 시도·자식·재시도의 비용 / 검증된 완료 과업 수
```

분모가 0이면 N/A다. 실패한 시도의 비용을 빼서 평균을 좋게 만들지 않는다. 사람의 검토 시간과 재작업도 따로 보고하며 금액에 합치려면 시간 단가와 측정 범위를 명시한다. 구독 화면의 추정 금액을 API 청구액으로 보고하지 않는다. A04의 예시 계산에는 cache write를 생략한 부분이 있으므로 위 식의 완전한 실측 사례로 쓰지 않는다.

## 모델과 effort는 별도로 조정한다

A05는 명세가 흐리면 높은 effort가 사용자 대신 내리는 결정을 늘릴 수 있다고 설명한다. 낮은 effort로 빠르게 방향을 확인하고 검증에 높은 effort를 쓰는 방식이 가능하지만, 낮은 effort도 실제 변경을 검증해야 한다는 A02의 조건은 남는다.

| 증상 | 먼저 점검할 것 — 위키 제안 |
|---|---|
| 원하는 결과가 매번 다름 | 명세·완료 조건·열린 결정 |
| 경계값을 반복해서 놓침 | 재현·관통 테스트·검증 예산 |
| 같은 잘못된 접근을 반복 | 가정·도구·평가기·모델 적합성 |
| 짧은 수정인데 출력이 큼 | 중복 지침·effort·불필요한 검토 반복 |
| 긴 세션의 입력 비용이 급증 | 캐시 만료·prefix 변화·모델/도구 전환 |
| 자식 실행 비용이 예상보다 큼 | 상속 모델·중복 작업·조정 비용·종료 여부 |

**출처 간 차이:** A04는 코드 편집을 Opus에 남기고 조회를 작은 모델에 배치하라고 권하지만 A02는 잘 정의된 코딩에 Sonnet을 권한다. 또한 같은 effort 명칭도 모델·플랫폼 간 계산량이 같지 않다. 따라서 일반적인 역할 분담 원칙과 특정 제품 추천을 분리하고, 대표 과업을 동일 조건에서 반복 평가한다. 모델 ID만 바꾸지 말고 content block·도구 스키마·thinking·거부·취소·진행 표시의 계약도 확인한다.

## 운영 루프: 계측에서 현장 검증까지

A06의 핵심은 에이전트 수가 아니라 다음 연결이다.

1. 사용자 여정의 시작·끝을 정의하고 비교 가능한 기준선을 만든다.
2. 빠르게 반복할 실험실 지표를 만들되 사용자 지연과의 연관을 검증한다.
3. 작은 변경과 테스트, 자동 검토, 사람 승인을 결합한다.
4. 위험 변경은 플래그와 점진 배포로 범위를 제한한다.
5. 빌드·플랫폼별 현장 지표를 읽고, 개선하지 않으면 중단하거나 되돌린다.
6. 확인한 개선은 CI 회귀 가드로 보존하고 임시 플래그를 정리한다.

저자들은 작업 흐름마다 사람 소유자가 사용자 경험·순서·범위를 판단했다고 설명한다. 유지보수 복잡도가 이익보다 크면 변경하지 않는 선택도 운영의 일부다. headless 환경에서 드러나지 않은 실제 브라우저 문제는 실험실 통과만으로 배포 안전을 보장할 수 없음을 보여준다.

### 약 3배라는 숫자의 범위

A06의 도표는 특정 두 시점에 측정한 13개 여정·표면의 p75 전후와 기하평균 약 3.1배를 제시한다. 모든 요청·p95·다른 제품에서 3배라는 뜻이 아니다. 이 저장소에서 재현하거나 독립 검증한 수치도 아니다. 사고 없음과 변경 규모 역시 저자 보고의 범위로 한정한다.

## 운영 대시보드의 최소 질문 — 제안

- **품질:** 무엇을 완료로 세었고, 검증하지 못한 것은 무엇인가?
- **지연:** 모델 응답 시간인가, 도구 시간인가, 사람이 결과를 쓸 수 있는 시간인가?
- **비용:** 재시도·자식·cache write까지 같은 범위에 포함했는가?
- **신뢰성:** 모델 실패, 도구 오류, 취소, 환경 장애를 구분했는가?
- **관측 범위:** 누락·만료·중단·샘플링을 0으로 바꾸지 않았는가?
- **배포:** 소유자, 승인, 중단 조건, 되돌릴 경로가 있는가?

이 항목을 자동 계측하는 기능을 이번 문서화에서 추가하지 않았다. [로컬 관측 대조](agent-evaluation-and-hillclimbing.md)는 현재 연결된 출처로 주장할 수 없는 지표도 명시한다.
