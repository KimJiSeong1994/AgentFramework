# 사람이 검토할 수 있는 에이전트 산출물

## 형식보다 검토 가능성

A11은 긴 Markdown보다 탐색·비교·시각화·상호작용이 있는 HTML을 선호하는 저자의 경험을 설명한다. 중요한 질문은 HTML 사용 자체가 아니라 사람이 실제로 내용을 읽고 판단할 수 있느냐다. 저자의 취향을 모든 문서의 형식 규칙으로 일반화하지 않는다.

A08은 코드·테스트·mockup·rubric도 고밀도 명세가 될 수 있다고 설명한다. A07은 결과의 변경 사항뿐 아니라 확인하지 못한 것과 사람이 결정해야 할 것을 드러내도록 권한다.

## 목적에 맞는 산출물 — 위키 종합

| 목적 | 보여줄 내용 | 검증과의 연결 |
|---|---|---|
| 대안 선택 | 접근별 장단점·비용·미확정 조건 | 선택 이유와 승인 범위를 기록 |
| 구현 검토 | 실제 diff·영향 경로·재현 가능한 문제 | 테스트 결과와 해당 변경 연결 |
| 디자인 검토 | 상태·오류·반응형·상호작용 | 선택 값을 JSON·diff 등으로 내보냄 |
| 조사 보고 | 주장·출처·반대 근거·미확인 | 독자가 원문까지 추적 가능 |
| 운영 보고 | 기준선·변경·표본·지연·오류·롤백 상태 | 같은 측정 범위인지 확인 |

A11의 일회성 편집 UI는 선택 결과를 다시 사용할 수 있는 형식으로 내보낼 때 유용하다. 화면에서 마음에 든 안을 선택한 것과 실제 코드·설정이 바뀐 것은 별개이며, 적용 뒤 다시 확인해야 한다.

## 표현과 권한을 분리한다

다음은 위키의 추가 안전 제안이다.

- 보기 좋은 보고서는 정확성의 증거도 승인 자체도 아니다.
- HTML의 스크립트·외부 리소스·공개 호스팅은 별도의 위험이다. 민감자료가 들어간 산출물을 편리하다는 이유로 외부 게시하지 않는다.
- 사용자 입력이나 원문에서 온 HTML을 신뢰된 코드로 실행하지 않는다.
- 검토 화면이 만든 명령·diff·설정은 검증된 입력으로 처리하고 기존 실행 권한을 그대로 적용한다.
- 시각화에 없는 원자료·제외 범위·불확실성을 감추지 않는다.

이 위키는 [기존 Markdown·불변 출처 규약](../../AGENTS.md)을 유지한다. HTML 배포나 자동 승인 기능을 추가한 것이 아니다. 실제 탐색은 [전체 글 목록](../entities/claude-dev.md)과 주제별 상대 링크로 제공한다.
