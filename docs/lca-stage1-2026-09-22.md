## 2. 실행 중 발견해 고친 것

1. **스킬 자동 발견이 프리픽스를 2K 토큰 잠식**: OpenCode가 `~/.claude/skills/synced`(Anthropic 스킬 8개)와 `~/.agents/skills`(orca 4개)를 자동 발견해 13개 스킬 설명(7,872자)을 skill 툴 스키마에 넣음. 바이너리 추적 결과 툴 설명에 실리는 목록은 **에이전트의 `permission.skill`이 deny가 아닌 것만**이라, main은 `config.skills.allow`(기본 `ulw`, `plan`)만 allow하고 나머지는 `"*": "deny"`, worker/reviewer는 skill 툴 자체를 끔. 프리픽스 8,290 → 4,945.
2. **바이트 기준 트리밍이 긴 절대경로에 무력**: `glob *` 결과 19,916바이트(상한 20,000 직전)가 실제로는 10,831 토큰. `guards.read_max_tokens`(기본 2,500)를 추가해 출력 자체의 바이트/토큰 비율로 바이트 예산을 줄이고, glob/grep/list/read/bash 출력에서 worktree 절대경로 접두를 제거(`relativize_paths`). 같은 호출이 1,730 토큰.
3. **컴팩션 가드**: 루프를 정지시키는 브레이커가 아니라 "이번 idle만 건너뛰기"로 변경(모드는 활성 유지).
4. **스캐폴드 버그**: `config.ts` 문서 주석 안의 `*/`가 파싱을 깨뜨림. 수정.
5. **webfetch**: main에서도 기본 off(툴 스키마 = 프리픽스). 프로젝트 설정으로 재활성 가능.

```
├── state/store.ts      .lca/state 원자적 쓰기, ModeState, 세션→agent 맵

├── hooks/chat-message.ts 키워드→모드 state, user 메시지 말미 ≤300자 지시(시스템 프롬프트 불변)
├── modes/{sanitize,detect,instructions}.ts  코드블록·URL·인용·정보성 질문 제외, 한국어 alias, 우선순위
├── guards/{repeat,trim,recover,repetition,todos,registry}.ts
├── hooks/tool-before.ts 동일 시그니처 재호출 차단(limit 2), 비-main의 task 차단
├── hooks/tool-after.ts  경로 상대화 → 토큰/바이트/줄 트리밍 → 복구 힌트

├── loop/idle.ts         브레이커(abort/max_iterations/ttl/stagnation/failures) + todo 기반 재프롬프트(promptAsync)
└── hooks/compacting.ts  ≤600자 체크포인트 주입 + checkpoint.json
scripts/lca-baseline.py  opencode.db 세션별 프리픽스/캐시미스/컴팩션/반복호출 표 + 타임라인
scripts/lca-doctor.sh    정적 검사 D01~D08 (--json)
scripts/lca-e2e.sh       XDG 격리(전역 OMO 설정·사용자 DB 미사용) + fib 픽스처 + E01~E04 판정
```

## 4. 확인된 OpenCode 동작 (코드/실행으로 검증)

- `tool.execute.before`에서 throw하면 툴 결과 오류 텍스트로 모델에 전달됨(dev 브랜치 소스 추적). 툴이 throw하면 `tool.execute.after`는 호출되지 않으므로 실패 집계는 `message.part.updated`의 `state.status==="error"`에서.
- `session.prompt`는 어시스턴트 턴이 끝날 때까지 블로킹 → 루프 재프롬프트는 `session.promptAsync`.
- `opencode debug config` 출력이 파이프에서 64KiB로 잘림. 파일로 리다이렉트 후 파싱.
- `XDG_CONFIG_HOME`/`XDG_DATA_HOME`을 존중함. `--pure`는 프로젝트 플러그인도 떨어뜨림.
- 이 셸의 `OPENCODE_CONFIG_DIR`(orca)이 별도 `opencode.json`으로 OMO를 로드함. doctor/e2e는 unset.
- 플러그인 `config` 훅의 `config.agent` 주입은 `debug config`/`debug agent`에 그대로 반영됨. OMO와 같이 로드되면 `default_agent`는 먼저 잡은 쪽(OMO)이 됨.

## 5. 사용법

```bash
cd framework && bun install && bun test          # 단위 테스트
bash scripts/lca-doctor.sh                       # 정적 검사
python3 scripts/lca-baseline.py --top 10         # 사용자 DB 기준선
bash scripts/lca-e2e.sh                          # 격리 e2e (모델 로드, ~1분)
```

실사용은 `~/.config/opencode/opencode.jsonc`의 `plugin` 배열에서 `oh-my-openagent@latest`를 제거한 뒤 이 저장소에서 OpenCode를 실행하면 `.opencode/plugins/lca.ts`가 로드된다(전역 설치 `scripts/setup.sh --with-lca`는 2단계에서도 미구현, 이월).

> **2026-09-22 2단계 리뷰에서 드러난 1단계 결함(수정됨)**: (1) config 훅의 에이전트 `tools:{...:false}`/`maxSteps`는 런타임에서 무시된다(스키마 디코드 이후라 permission/steps로만 반영됨) → `task`·`todowrite`가 모든 에이전트에 노출돼 있었음. (2) `chat.params`의 `reasoning_effort`(snake_case)는 AI SDK가 무시 → 워커 thinking OFF가 적용되지 않았음. (3) `.lca/state`가 워크트리 안에 있었음(현재 `$XDG_STATE_HOME/lca/`). 상세는 `docs/lca-stage2-2026-09-22.md` 7절.
