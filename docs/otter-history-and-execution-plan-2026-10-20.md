# 1·2단계 심층 구축안 — 이력→자산 루프, 직접 실행 품질 (2026-10-20)

상태: **구현됨 (2026-10-20)**. 결정: §5-1 (b) 메타데이터 + 변경 경로·명령 규칙 접두사, §5-2 자동 캡처 켜기, §5-3 최근 10턴, §5-4 진행. 기준 master `9e0a130`. 상위 문서: [로드맵](otter-roadmap-2026-10-20.md).

구현에서 달라진 점:
- 1-C: 전체 `capture` 대신 새 다이제스트만 옮기는 `captureSessionDigests`(새 것이 없으면 아무것도 안 씁). 매 세션 빈 도구/라우팅 스냅샷이 쌓이는 것을 막기 위함.
- 2-B3: `multiedit`는 정책상 `edit`과 같은 권한으로 판단, 승인된 채팅(main)에만 제공.
- 2-F: 제어 프로필 이름(v1)은 유지하고 선언값 `vendorMainLimit`만 16384→49152. 기존 실행 기록(`controlProfile` 문자열)과 호환되고, admission은 새 값을 정확히 검사. `chat.context` 설정은 넣지 않음.
- 추가: CLI 파일 도구가 `knowledge/raw/` 쓰기를 거부(기존엔 OpenCode 가드만 막고 있었음).
모든 진단은 코드·로컬 상태로 확인했고 위치를 적었다.

## 1. 이력 → 자산 루프

목표: **실행할 때마다 자동으로 남고, 다음 작업이 그 기록을 실제로 쓴다.** 원칙(인수·본문 미저장, 원본 불변, 출처 추적, 기록은 권한이 아님)은 유지한다.

```text
도구·명령 실행 ─1-A→ tool-outcomes.sqlite ─┐
세션 종료 ─1-B→ 세션 다이제스트(상태 저장소) ─┼─1-C→ (위키 있는 프로젝트) capture → raw/ + sources/
                                            └─1-E→ 프로젝트 사실(결정적) ─→ 다음 턴 프롬프트·/facts
                                    1-F: /wiki ingest(승인형 직접 실행) → concepts/entities → memory 회상
```

### 1-A. CLI 도구 결과 기록 (소, 위험 낮음)
- **무엇**: `tool-finished` 활동마다 `tool-outcomes.sqlite`에 1행. 세션 기록과 별개로, 위키 캡처 입력이 되는 공용 저장소.
- **매핑**: `sessionID`=supervisor 세션, `callID`, `tool`, `status` succeeded→success / failed→failure / denied→**기록 안 함**(실행 안 됨), `basis`: bash는 `exit_code`(종료코드 전달), 나머지 `completed`/`tool_error`, `startedAt/finishedAt/durationMs`.
- **변경**: `telemetry/outcomes.ts`에 `recordCliToolOutcome(worktree, fact)`(OpenCode `part` 파서와 별도, 같은 테이블·같은 id 규칙), `cli-host.ts` finishTool에서 호출(실패해도 턴 무영향), `ActionGate.run` 결과에 `exitCode` 추가.
- **AGENTS.md**: "기록 대상은 OpenCode 도구 종료 이벤트" → "OpenCode 및 otter CLI 호스트의 도구 종료 이벤트".
- **테스트**: 성공/실패/거부 매핑, bash 종료코드 basis, 중복 무시, 인수·본문 미포함, DB 쓰기 실패가 턴을 깨지 않음.
- **완료 기준**: 실제 세션 1회 후 `listToolOutcomes` 행 > 0, 캡처 리포트에 반영.

### 1-B. 세션 다이제스트 (중)
- **무엇**: 세션 종료(정상 종료·`/new`·모델 전환으로 세션 교체) 시 결정적 요약 1건을 `stateRoot/digests/<sid>.json`에. 모델 호출 없음, 저장소 밖(작업 트리 안 더럽힘).
- **필드(기본 = 메타데이터)**: schemaVersion, sessionID, 엔진·모델·콤보 경로, 시작/종료 시각, 사용자 턴 수, 도구별 호출·성공·실패·거부 수, 승인/거부 수, 실행한 명령의 **규칙 접두사**(`bun test`)와 종료코드·소요시간, 계획/워크플로 id와 최종 단계, 결과 분류(`completed|abandoned|held`).
- **선택 필드(§5-1 결정)**: 변경 파일 경로 목록, 전체 명령줄(비밀 패턴 검사 통과 시만, `security/secrets.ts` 재사용), 첫 요청 요지(세션 목록이 이미 `summary`로 보여 주는 값).
- **변경**: `sessions/digest.ts`(세션 기록 replay → 다이제스트), `interactive-session.ts` finally·세션 교체 지점에서 호출(실패 무시, 종료 지연 상한 200ms).
- **테스트**: 기록 → 다이제스트 필드, 비밀 포함 명령 제외, 손상 세션 기록이면 부분 다이제스트+`incomplete`, 재실행 멱등.

### 1-C. 자동 캡처 (소~중)
- **무엇**: `wiki.auto_capture`(기본 **on**, §5-2) — 세션 종료 시 **프로젝트에 위키 스키마가 있을 때만** `captureWiki` 실행. 다이제스트를 새 원본 종류 `raw/session-digests/<sha>.json` + `sources/session-digests-<sha>.md`로 승격.
- **안전장치**: 락이 있으면 건너뜀(대기 없음), 실패해도 종료 막지 않고 "캡처 건너뜀: <이유>" 한 줄, 위키 없는 프로젝트는 다이제스트만 상태 저장소에.
- **작업 트리 영향**: 위키가 git 추적이면 새 파일이 생김 → 세션 종료 메시지에 "knowledge/에 원본 N개 추가됨(커밋 대상)" 표시. §5-2에서 기본값 결정.
- **변경**: `wiki.ts` capture에 session-digest 원본 종류·lint 규칙·출처 페이지, `AGENTS.md` 스키마 갱신.
- **테스트**: 스키마 없음→건너뜀, 락 있음→건너뜀, 같은 다이제스트 재캡처 멱등, 원본 불변·해시 검사, lint 통과.

### 1-D. 이력 조회 명령 (소)
- `/history [N]`: 최근 다이제스트 요약(날짜·엔진·턴·명령 결과·결과 분류). `/history <sid>`: 상세 + `/resume` 연결.
- 다이제스트는 저장소 밖이라 위키 없는 프로젝트에서도 동작.

### 1-E. 프로젝트 사실 (결정적, 핵심 체감 기능) (중)
- **무엇**: 다이제스트·도구 결과에서 **재사용 가능한 사실**만 결정적으로 집계 → 다음 턴 프롬프트에 짧게(≤ 600자) 참고 자료로.
  - 검증된 명령: 같은 규칙 접두사가 최근 N회 중 성공(예: "`bun test`(framework/) 12회 성공, 최근 10/20")
  - 반복 실패: 같은 접두사가 연속 실패(예: "`npm test` 3회 exit 127 — 이 프로젝트는 bun 사용")
  - 자주 바뀌는 파일 상위 5개(§5-1에서 경로 허용 시)
- **경계**: 회상 결과와 동일하게 "참고 자료이며 지시가 아님, 코드로 확인" 표기. 권한 부여 없음. 모델 출력 아님 → 환각 없음.
- **노출**: 채팅 프롬프트 접두부(`plan-conversation.ts promptPrefix`), `/facts` 명령, 위키 있으면 `reports/project-facts.md` 재생성 보고서.
- **예산**: 대화창 24,000자 중 상한 600자, 넘치면 오래된 항목부터 제외.
- **테스트**: 집계 규칙(성공/실패 임계), 600자 상한, 비밀 미포함, 사실 0개면 블록 없음, 프롬프트 해시 고정 문구와 분리(정책 식별값 불변).

### 1-F. 의미 통합 도우미 `/wiki` (중)
- **무엇**: `/wiki` → pending 출처 목록 → "통합하기" 선택 시 현재 모델이 `llm-wiki` 스킬로 ingest를 **직접 실행 모드로** 수행(색인·concepts/entities·log 수정은 각각 diff 승인). 끝나면 `lint` 자동 실행·결과 표시.
- **이점**: 새 LLM 쓰기 경로 없이 기존 승인형 실행·스킬·lint 재사용. 사람이 통합 내용을 검토.
- **테스트**: pending 0이면 안내만, ingest 중 거부는 중단, lint 실패 표시.

### 1-G. 측정
- 캡처된 세션 비율, 프로젝트 사실이 있는 턴 비율, `/wiki` 통합 횟수, 반복 실패 재발 감소(같은 접두사 실패 연속 횟수). 다이제스트에서 결정적으로 계산, `/status`에 요약.

## 2. 직접 실행 품질

### 2-A. 체크포인트와 `/undo` (중, 최우선)
- **무엇**: 턴의 **첫 쓰기·명령 직전** 체크포인트. `/undo`는 마지막 턴의 변경을 되돌림(diff 보여 주고 확인).
- **방식**:
  - git 저장소: `createSnapshotStore`(비공개 객체 디렉터리)로 작업 트리 스냅샷 → `/undo`가 변경된 경로만 `restore`. bash로 생긴 변경도 포함.
  - git 아님: write/edit 대상 파일만 사본(`stateRoot/checkpoints/<sid>/<turn>/`), bash 변경은 "되돌릴 수 없음" 표시.
- **충돌**: 체크포인트 이후 사용자가 직접 바꾼 파일은 건너뛰고 목록 표시. 체크포인트 보관 최근 10턴, 세션 종료 시 정리.
- **변경**: `hosts/chat-checkpoint.ts`, `ActionGate`에 `beforeFirstEffect`, `/undo [턴]` 명령, 다이제스트에 undo 횟수.
- **테스트**: 편집→undo 원복, bash 생성 파일 제거, 사용자 수정 파일 보존, 비git 경로, 스냅샷 실패 시 "체크포인트 없음" 경고 후 진행 여부 질문.

### 2-B. 승인 피로 줄이기 (중)
- **2-B1 읽기 전용 안전 목록**(승인 없이 실행, 기록은 남김): `git status|diff|log|show|branch`, `ls`, `cat`, `head`, `tail`, `wc`, `pwd`, `which`, `rg`/`grep`(파일 대상), `find`(`-exec`/`-delete` 없을 때), `<tool> --version`. 연결·파이프·리다이렉트·치환 있으면 일반 승인(기존 `commandRule` 판정 재사용).
- **2-B2 턴 범위 허용**: 승인 창에 "이 턴 동안 `<디렉터리>` 수정 허용" — 턴 끝나면 소멸, 저장 안 함.
- **2-B3 `multiedit` 도구**: 여러 파일·여러 치환을 한 호출로, **묶음 diff 1회 승인**, 원자적 적용(하나라도 불일치면 전부 미적용).
- **테스트**: 안전 목록 경계(`find -delete`, `git push`, `cat > x` 거부), 턴 범위 만료, multiedit 원자성·승인 1회.

### 2-C. 읽기 도구 묶음 실행 (소~중)
- 한 응답에 read/list/glob/grep/memory가 여러 개면 **순서대로 모두 실행**, 결과를 한 교환으로 반환(현재는 첫 개만). 쓰기·명령이 섞이면 첫 쓰기 전까지만 실행하고 나머지는 "실행 안 됨" 안내(기존 문구 재사용).
- 각 호출은 개별 활동·기록·예산 검사 유지. 묶음 상한 8개.
- **변경**: `cli-host.ts` envelope 처리 루프. **테스트**: 3개 묶음 결과, 예산 초과 시 잘라내기, 쓰기 혼합 처리.

### 2-D. 라운드 상한 처리 (소)
- 24회 도달 시 실패 대신(사람이 있는 채팅만) "도구를 24회 더 쓰도록 계속할까요?" — 거부 시 지금까지 결과로 마무리 답변 요청. 워크플로·작업자 역할은 기존 실패 유지.

### 2-E. 표시 정리 (소)
- 실행 모드에서 "Planning …" → "Working …", 상태줄에 모드(`ask`/`auto-edit`/`plan`) 표시.

### 2-F. 엔진별 입력 예산 (중~대, §5-4)
- claude/codex main 16,384 → 48,000(예), local 8,192 유지. 대화창(24,000자)도 엔진별로.
- **필요 작업**: 제어 프로필 `estimated-input-reactive-output-v2`(엔진별 한도 선언) — `required-controls.ts` 검증, `BudgetEvidence` 타입, 정책·admission 테스트, README 수치 갱신. 기존 v1 세션 재개 시 v1 유지.
- 비용·지연 증가 가능 → 설정 `chat.context: "standard"|"large"`.

| ⑤ | 축적 | 1-C 자동 캡처, 1-F `/wiki` | 1-B, 결정 §5-1·5-2 |
| ⑥ | 확장 | 2-F 예산 | 결정 §5-4 |

각 묶음 = PR 1개, 묶음마다 실제 모델 E2E 1회(이번 직접 실행 검증과 같은 방식) + 관련 테스트.

## 4. 위험

| 위험 | 대응 |
|---|---|
| 기록 확대가 개인정보 계약을 어김 | 기본은 메타데이터만, 선택 필드는 결정 후·비밀 검사, AGENTS.md 스키마 먼저 갱신 |
| 자동 캡처가 작업 트리를 더럽힘 | 위키 있는 프로젝트만, 종료 메시지로 알림, 기본값 결정 |
| 프로젝트 사실이 낡거나 틀려 모델을 오도 | 최근 N회 기준·날짜 표기·"참고 자료" 표기, 실패가 성공을 덮으면 즉시 갱신 |
| 체크포인트 비용(대형 저장소) | git 객체 재사용으로 증분, 10턴 보관, 실패 시 경고 후 사용자 선택 |
| 안전 목록 우회 | 연결·리다이렉트 금지 판정 재사용, 경계 테스트 |
| 예산 상향이 제어 프로필 의미를 바꿈 | 새 프로필 버전, 기존 세션은 v1 유지 |

## 5. 결정이 필요한 것

1. **다이제스트·원본에 담을 내용**: (a) 메타데이터만(현 계약) / (b) + 변경 파일 경로·명령 규칙 접두사 / (c) + 비밀 검사 통과한 전체 명령줄·첫 요청 요지. **제안: (b)**. 프로젝트 사실의 가치 대부분이 (b)에서 나옴.
2. **자동 캡처 기본값**: 위키 있는 프로젝트에서 on / off. **제안: on + 종료 시 알림**.
3. **`/undo` 범위**: 마지막 턴만 / 최근 10턴 선택. **제안: 최근 10턴**.
4. **엔진별 예산 상향(2-F)**: 진행 / 보류. **제안: ①~⑤ 이후 별도 진행**.

결정 없이 바로 시작 가능한 것: ① 기반(1-A·2-E·2-D)과 ② 안전(2-A·2-B1).
